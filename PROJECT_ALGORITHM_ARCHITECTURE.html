cartesian_controllers_ros2 算法原理与架构图

本项目是面向 ROS 2 control 的笛卡尔空间可变阻抗控制器集合，核心包为 cartesian_vic_controller，并提供状态广播、MoveIt Servo 版本和双边遥操作扩展。

1. 项目总体定位

仓库围绕 6 维笛卡尔位姿、速度、加速度、力/力矩和柔顺参数构建控制链路。主控制器从 ros2_control 硬件接口读取关节状态和可选力传感器数据，通过动力学/运动学插件计算末端状态、雅可比和惯量，再由 VIC 规则插件生成关节位置/速度或力矩命令。

cartesian_control_msgs定义 CartesianState、CompliantFrameTrajectory、VicControllerState、TeleopControllerState 等消息。
cartesian_state_broadcaster读取关节 position/velocity，利用 kinematics_interface 发布末端 pose 和 twist。
cartesian_vic_controller主控制器，基于 ros2_control 和 pluginlib，提供导纳、阻抗、twist 导纳三类规则。
cartesian_vic_servo将 VIC 规则输出的 twist 命令交给 MoveIt Servo，再生成 JointTrajectory。
cartesian_vic_teleop_controller继承 VIC 主控制器，增加 leader/follower 映射、clutch、双边柔顺参考生成。

3. VIC 控制算法原理

VIC 表示 Variable Impedance Control。控制目标是在末端笛卡尔空间呈现期望的质量-阻尼-刚度行为，同时允许参考力/力矩参与交互控制。

状态、误差和力定义如下。项目代码使用几何雅可比 J(q)，末端速度为 6 维 twist，姿态误差使用旋转矩阵误差的 angle-axis 表示。

q, qdot : 关节位置与速度 x = [p; theta] : 末端 6D 笛卡尔状态，theta 用 angle-axis 误差表达 xd = [pd; thetad] : 期望笛卡尔状态 e = xd - x edot = xdot_d - xdot w_ext = [force; torque] : 末端外部 wrench，代码中由 F/T 传感器转换到 base frame

机械臂关节空间动力学模型：

H(q) qddot + C(q, qdot) + G(q) = tau_cmd + J(q)^T w_ext

期望笛卡尔柔顺行为：

M e_ddot + D e_dot + K e = w_ext - w_ref

将误差定义代入后，控制器计算的笛卡尔加速度命令为：

xddot_cmd = xddot_d + M^-1 (K e + D e_dot - w_ext + w_ref)

M、D、K 是 6x6 笛卡尔惯量、阻尼和刚度矩阵。默认参数只配置 6 个对角值，代码会组成对角矩阵并把它们从 vic.frame.id 旋转到机器人 base frame。阻尼可由阻尼比生成：

D_i = 2 zeta_i sqrt(M_i K_i), i = x, y, z, rx, ry, rz

若 vic.use_natural_robot_inertia = true，则期望惯量不取参数矩阵，而使用动力学插件计算的机器人自然笛卡尔惯量：

Mx(q) = (J(q) H(q)^-1 J(q)^T)^-1 M = Mx(q)

导纳控制 VanillaCartesianAdmittanceRule

导纳模式把外力引起的笛卡尔加速度积分为关节速度和关节位置命令，适合 position/velocity 命令接口。

qddot_cmd = J# (xddot_cmd - Jdot(q, qdot) qdot) qdot_cmd(k) = qdot_cmd(k-1) + qddot_cmd Ts q_cmd(k) = q_cmd(k-1) + qdot_cmd(k) Ts

实现中还会检查雅可比条件数，使用阻尼伪逆：

J# = (J^T J + alpha I)^-1 J^T

若启用 nullspace 控制，导纳规则会增加一个投影到零空间的关节加速度项：

N = I - J# J qddot_null = N M_null^-1 (-D_null qdot + K_null (q_null_d - q) + tau_ext) qddot_cmd = qddot_cmd + qddot_null

最后可对 qdot_cmd 做指数平滑，以降低命令抖动。

阻抗控制 VanillaCartesianImpedanceRule

阻抗模式先把笛卡尔加速度映射到关节加速度，再用动力学模型生成力矩命令，适合 effort 命令接口。

qddot_cmd = J# (xddot_cmd - Jdot(q, qdot) qdot)

非自然惯量分支的力矩命令为：

tau_raw = H(q) qddot_cmd + J(q)^T w_ext

若启用重力/科氏补偿：

tau_cmd = tau_raw + C(q, qdot) + G(q)

若未启用补偿：

tau_cmd = tau_raw

自然惯量分支会用 Mx(q) 作为期望惯量，并按代码中的简化阻抗形式计算关节加速度，再乘以关节惯量对角项形成原始力矩：

qddot_cmd = J# (xddot_d - Jdot qdot) + J^T (K e + D e_dot + w_ref) tau_raw = diag(H(q)) qddot_cmd

Twist 导纳 TwistCmdCartesianAdmittanceRule

该规则只输出笛卡尔 twist，不在 VIC 内部做逆运动学。它服务于 cartesian_vic_servo，由 MoveIt Servo 将 twist 转换成关节轨迹。

twist_cmd(k) = twist_cmd(k-1) + xddot_cmd Ts

4. 主控制器实时链路

主循环入口是 CartesianVicController::update()。生命周期上，on_configure() 加载 URDF、参数、VIC 规则插件和传感器语义组件；第一次收到有效状态后，以当前末端位姿初始化参考；之后每个周期读取硬件状态、更新参考、调用规则插件、写入硬件命令并发布状态。

5. Teleop 与 Servo 扩展链路

cartesian_vic_teleop_controller 不直接替换底层 VIC，而是在主 VIC 控制循环前加入遥操作逻辑：读取 follower 的 VicControllerState、读取 teleop compliance 和 clutch 状态，计算 leader/follower 两套 CompliantFrameTrajectory。leader reference 回灌到本机 VIC，follower reference 通过 topic 发给从端控制器。

cartesian_vic_servo 则是另一条执行路径：VIC 规则只计算 twist，MoveIt Servo 负责把 twist 变成关节轨迹。它要求实时获取 joint state、wrench 和 reference trajectory，若状态或参考超时则发布零 twist 作为回退策略。

6. 需要接入的硬件数据

按当前代码，硬件接入主要通过 ros2_control state/command interfaces 和 semantic components 完成。下面按“必须/按模式/可选”列出。

硬件数据或接口是否需要接入形式用途
每个受控关节的位置 q 必须 <joint>/position state interface 初始化参考位姿、FK、Jacobian、动力学模型、控制误差计算。
每个受控关节的速度 qdot 必须 <joint>/velocity state interface 末端 twist、Jdot qdot、加速度估计、阻尼项和动力学补偿。
关节位置命令接口 导纳常用 <joint>/position command interface 导纳控制可输出积分后的 q_cmd。若只用速度控制，可不声明该命令接口。
关节速度命令接口 导纳推荐 <joint>/velocity command interface 导纳控制主要输出 qdot_cmd，README 中也建议导纳优先接 velocity group。
关节力矩/力命令接口 阻抗必须 <joint>/effort command interface 阻抗控制输出 tau_cmd，没有 effort command interface 不能运行阻抗模式。
六维力/力矩传感器 wrench 按模式 ForceTorqueSensor semantic component，配置 ft_sensor.name 和 ft_sensor.frame.id 导纳控制需要外部 wrench；阻抗非自然惯量分支也需要外力估计。可配置滤波和末端重力补偿。
外部关节力矩 可选 external_torque_sensor semantic component 用于 nullspace 控制中的外部力矩项；不开启 nullspace 时通常不需要。
URDF / robot_description 必须 ROS 参数 robot_description，或从 robot_state_publisher 获取 动力学插件需要模型结构、关节、base/tip、传感器 frame。
动力学/运动学插件配置 必须 dynamics.plugin_name、dynamics.plugin_package、dynamics.base、dynamics.tip 计算 FK、J、Jdot、H、C、G 和自然笛卡尔惯量。
Servo 分支的 joint state 与 wrench topic Servo 需要 MoveIt planning scene monitor 当前状态；~/wrench topic cartesian_vic_servo 不直接 claim ros2_control 接口，而从 MoveIt/Topic 获取状态并向 MoveIt Servo 发送 twist。
Teleop follower 状态与 clutch Teleop 需要 /vic_controller_follower/status、fd_clutch、~/teleoperation_compliance_reference 双边遥操作计算 leader/follower 两端参考，clutch 控制工作空间映射是否接合。

最小接入组合

  • 仅运行状态广播器：关节 position 和 velocity state interfaces，外加 URDF 和 kinematics plugin。
  • 运行导纳 VIC：关节 position/velocity state interfaces，velocity 或 position+velocity command interfaces，通常还需要 F/T wrench。
  • 运行阻抗 VIC：关节 position/velocity state interfaces，effort command interface，若不用自然惯量分支则需要 F/T wrench。
  • 运行 MoveIt Servo 分支：MoveIt 可用的实时 joint state、F/T wrench topic、MoveIt Servo 输出的 JointTrajectory 下游控制器。
  • 运行双边 Teleop：leader 本机硬件数据 + follower VIC /status + follower reference topic + clutch/compliance 输入。

7. 硬件接口和 Topic 消息格式

主 cartesian_vic_controller 是 ros2_control 控制器，关节和六维力数据通过 hardware interface 进入控制器，不是通过普通 sensor_msgs/JointState topic。Servo 与 Teleop 分支才额外使用 ROS topic。

关节硬件接口

<joint_name>/position <joint_name>/velocity <joint_name>/effort # 阻抗 effort 控制需要

硬件侧每个周期至少提供所有受控关节的 position 和 velocity。导纳控制写回 velocity 和可选 position；阻抗控制写回 effort。

cartesian_vic_controller: ros__parameters: joints: [joint_a1, joint_a2, joint_a3, joint_a4, joint_a5, joint_a6, joint_a7] state_interfaces: [position, velocity] command_interfaces: [velocity] # 导纳推荐；阻抗使用 [effort]

六维力/力矩传感器接口

主 VIC 控制器使用 ros2_control ForceTorqueSensor semantic component。硬件插件需要导出以下 6 个 state interfaces：

<ft_sensor.name>/force.x <ft_sensor.name>/force.y <ft_sensor.name>/force.z <ft_sensor.name>/torque.x <ft_sensor.name>/torque.y <ft_sensor.name>/torque.z
ft_sensor: is_enabled: true name: ftsensor frame: id: ft_sensor

force 单位为 N，torque 单位为 N·m，ft_sensor.frame.id 是 wrench 所在坐标系，并且必须能通过 URDF/TF 与 base 和末端 frame 建立关系。

外部关节力矩接口

若启用 external_torque_sensor，默认接口名为：

<external_torque_sensor.name>/external_torque.joint_a0 <external_torque_sensor.name>/external_torque.joint_a1 ... <external_torque_sensor.name>/external_torque.joint_a<N-1>

该数据主要用于 nullspace 控制中的外部力矩项，未启用 nullspace 时一般不需要。

9. 未来可应用场景

当前项目的核心价值是把末端笛卡尔空间的轨迹跟踪、柔顺交互、力反馈和 ROS 2 control 硬件接口打通。因此它未来适合用于“需要接触环境、需要安全柔顺、需要远程/双边操作”的机器人系统。

应用场景适合的控制形态需要重点接入的数据落地价值
力控装配与插拔 导纳 VIC 或阻抗 VIC 高频关节状态、末端 F/T wrench、准确 TCP/工具坐标、刚度/阻尼参数在线调整 适合 peg-in-hole、接插件插拔、卡扣装配、端子压接等存在接触约束的任务，机器人可以在受力后自动让位或保持期望接触力。
表面跟随与恒力加工 导纳 VIC F/T 传感器、末端轨迹参考、工具重力补偿参数、速度/位置命令接口 适合打磨、抛光、去毛刺、擦拭、喷涂前贴近曲面等任务，通过低刚度方向顺应表面，高刚度方向保持轨迹。
人机协作与安全拖动 导纳 VIC + 低刚度参数 关节状态、F/T 或外部力估计、速度命令接口、安全限速/限力层 可用于示教拖动、协作搬运、共享工作空间中的顺应避让，让机械臂对外力更柔和。
双边遥操作 cartesian_vic_teleop_controller leader/follower 两端 VicControllerState、两端 F/T wrench、clutch、teleop compliance 适合危险环境、远程实验、核工业/化工/救援等场景。leader 端可渲染 follower 的接触状态，follower 端跟随 leader 操作意图。
移动操作机器人 VIC + MoveIt Servo 分支 MoveIt planning scene、joint state、wrench topic、JointTrajectory 下游控制器 适合移动底盘加机械臂系统，在动态环境中通过 MoveIt Servo 处理速度命令、限速和碰撞相关约束。
康复、辅助与外骨骼类交互 导纳 VIC 或遥操作逻辑扩展 人体交互力、关节状态、安全冗余传感器、严格限力限速 适合需要柔顺人机交互的研究原型，例如被动引导、力辅助训练、低阻抗跟随。真机应用需要额外医疗级安全认证与冗余保护。
教学科研平台 所有 VIC rule 插件 仿真或真实机械臂模型、可切换的 dynamics plugin、日志/状态 topic 适合比较导纳、阻抗、自然惯量、nullspace、滤波和不同柔顺参数对系统响应的影响。

适配路线

  • 短期最容易落地的是仿真验证、状态广播、导纳式柔顺跟踪和 MoveIt Servo twist 分支，因为对底层硬件力矩控制要求较低。
  • 中期可扩展到打磨、擦拭、装配等接触任务，关键是稳定 F/T 数据、工具重力补偿、合理的限速限力和任务级状态机。
  • 长期可发展为双边遥操作和移动操作系统，重点会转向网络延迟、passivity、clutch 映射、碰撞约束、故障回退和多传感器融合。

当前项目还需要补强的能力

  • 奇异规避仍不完整，现有代码主要是条件数告警/报错，真机复杂任务需要更平滑的缩放或约束优化策略。
  • 力控任务需要完善工具负载辨识、F/T 零偏校准、接触状态检测和异常力回退策略。
  • 工业应用需要加入任务层安全壳，例如最大速度、最大力、工作空间边界、碰撞监测和急停联动。
  • 遥操作应用需要进一步处理通信延迟、丢包、能量一致性和 leader/follower 缩放映射。

10. 运行时注意点

  • 主 VIC 控制器要求关节 position 和 velocity 状态接口同时存在。
  • 导纳控制通常需要 F/T 传感器；阻抗控制在非自然惯量模式下也依赖外力估计。
  • 导纳模式输出 position/velocity 命令；阻抗模式输出 effort 命令；servo 分支输出 twist 并交给 MoveIt Servo。
  • 代码中已有雅可比条件数告警/停止逻辑，但 README 也明确指出默认 VIC 的奇异规避策略仍不完整，真机使用需要额外安全层。
  • 控制器使用 realtime buffer 和 realtime publisher，控制循环内避免非实时阻塞操作。
